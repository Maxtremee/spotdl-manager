## Directory Purposes

**`src/routes/`:**
- Purpose: File-based routing declarations; one file per URL path
- Contains: Route modules exporting `Route = createFileRoute(...)` with optional `loader`, `validateSearch`, `loaderDeps`, `component`
- Key files: `__root.tsx` (shell), `index.tsx` (`/`), `library.tsx`, `library_.$playlistId.tsx`, `library_.add.tsx`, `settings.tsx`, `status.tsx`
- Note: Nested flat routes use `_` prefix (e.g., `library_.add.tsx` = `/library/add` without inheriting `library.tsx` layout)

**`src/modules/client/`:**
- Purpose: Browser-safe feature code bundled into the SPA payload
- Contains: `{feature}/components/`, `{feature}/schema/`, `{feature}/service/`, `{feature}/utils/`
- Key files:
  - `src/modules/client/playlist/schema/playlist.ts` — canonical Zod `PlaylistSchema`
  - `src/modules/client/playlist/utils/mapper.ts` — `rowToPlaylist` / `playlistToRow`
  - `src/modules/client/playlist/service/playlist-actions.ts` — client-side action wrappers around server fns
  - `src/modules/client/invocation/service/duration.ts` — formatters
- Rule: Never import from `src/modules/server/`

**`src/modules/server/`:**
- Purpose: Server-only code (Nitro/Node runtime)
- Contains: `{feature}/functions.ts` (server functions), `{feature}/repository.ts` (Drizzle queries), plus feature-specific classes (scheduler, invocator, event bus)
- Key files:
  - `src/modules/server/db/schema.ts` — Drizzle table definitions
  - `src/modules/server/db/index.ts` — `getDb()` singleton
  - `src/modules/server/playlist/functions.ts` — list/create/update/delete + `triggerPlaylistSyncServerFn`
  - `src/modules/server/scheduler/PlaylistScheduler.ts` — cron scheduler singleton
  - `src/modules/server/spotdl/SpotdlInvocator.ts` — spotdl CLI wrapper
  - `src/modules/server/events/EventBus.ts` — pub/sub singleton
- Rule: May import Zod schemas/types from `src/modules/client/{feature}/schema/*` (types are isomorphic), but never client components

**`src/components/`:**
- Purpose: App-wide shared components that are not feature-scoped
- Contains: `nav.tsx`, `generic-error.tsx`, `not-found.tsx`, and the `ui/` kit
- Note: Feature-scoped components live under `src/modules/client/{feature}/components/`

**`src/components/ui/`:**
- Purpose: 61 pre-built component wrappers around Ark UI primitives, styled via PandaCSS recipes
- Contains: `button.tsx`, `card.tsx`, `dialog.tsx`, `toast.tsx`, `input.tsx`, `select.tsx`, etc.
- Rule: Always import UI from here rather than raw `@ark-ui/solid`

**`src/theme/`:**
- Purpose: PandaCSS theme customization consumed by `panda.config.ts`
- Contains: `colors/`, `recipes/`, `tokens/`, plus top-level styling modules
- Output: Generated into `styled-system/` by `pnpm prepare`

**`server/plugins/`:**
- Purpose: Nitro startup plugins referenced from `vite.config.ts`
- Contains: `events.ts` (registers EventBus handlers), `scheduler.ts` (initializes PlaylistScheduler)
- Runs: Once at Nitro server boot; cleanup on `close` hook

**`drizzle/`:**
- Purpose: Auto-generated SQL migrations
- Generated: Yes (via `pnpm db:generate`)
- Committed: Yes
- Rule: Never hand-edit; add a new migration instead

**`styled-system/`:**
- Purpose: PandaCSS codegen output (utilities, patterns, recipes, tokens, types)
- Generated: Yes (via `pnpm prepare` / `panda codegen`)
- Committed: Yes
- Rule: Never hand-edit; change `panda.config.ts` or files under `src/theme/` and regenerate

**`data/`:**
- Purpose: Runtime application state
- Contains: `db.sqlite` (Drizzle target), `logs/` (spotdl stdout/stderr), `sync/` (`*.spotdl` state files)
- Committed: No — gitignored

**`public/`:**
- Purpose: Static assets served at site root
- Contains: `favicon.ico`, logos, `manifest.json`, `robots.txt`

**`patches/`:**
- Purpose: pnpm patch-package overrides for upstream deps

## Naming Conventions

**Files:**
- `kebab-case.tsx` / `kebab-case.ts` for most modules (e.g., `playlist-actions.ts`, `recent-runs-table.tsx`, `discord-webhook-service.ts`)
- `PascalCase.ts` for classes that map 1:1 to the file (e.g., `PlaylistScheduler.ts`, `SpotdlInvocator.ts`, `EventBus.ts`)
- Fixed feature-module filenames: `repository.ts`, `functions.ts`, `schema.ts`, `service.ts`, `handler.ts`, `index.ts`
- Route files follow TanStack flat-route syntax: `library.tsx`, `library_.add.tsx`, `library_.$playlistId.tsx`, `library_.$playlistId_.logs_.$logId.tsx`
- Tests live next to the source file as `<name>.test.ts`

**Directories:**
- `kebab-case` or single lowercase word per feature (`playlist`, `invocation`, `webhooks`, `scheduler`, `spotdl`)
- Standard subfolders within a feature: `components/`, `schema/`, `service/`, `utils/` (client) and no fixed subfolder structure on server (flat `repository.ts` + `functions.ts`)

**Identifiers:**
- Server function suffix: `XxxServerFn` (e.g., `listPlaylistsServerFn`, `updateWebhookSettingsServerFn`)
- Repository export: `XxxRepository` (object literal or class)
- Zod schemas: `XxxSchema`; inferred types: `Xxx` (e.g., `PlaylistSchema` + `type Playlist`)
- Event types: dotted lowercase (e.g., `playlist.sync.completed`, `scheduler.reload`)

## Where to Add New Code

**New Route / Page:**
- Create file under `src/routes/` matching TanStack flat-route naming
- Export `Route = createFileRoute("/path")({ loader?, validateSearch?, component })`
- Run dev server or build to regenerate `src/routeTree.gen.ts`

**New Feature Module (client-side UI + forms):**
- Create `src/modules/client/{feature}/` with subfolders:
  - `schema/` — Zod schema + inferred type
  - `components/` — Solid components for the feature
  - `service/` — client-side helpers (formatters, action wrappers around server fns)
  - `utils/` — pure helpers (e.g., row mappers)
- Optionally add `index.ts` barrel (example: `src/modules/client/settings/index.ts`, `src/modules/client/webhooks/index.ts`)

**New Feature Module (server-side data + API):**
- Create `src/modules/server/{feature}/`:
  - `repository.ts` — Drizzle queries; call `getDb()` from `../db`
  - `functions.ts` — `createServerFn(...).inputValidator(...).handler(...)` exports
  - `schema.ts` — server-only Zod schemas (for settings rows, etc.) when needed
  - Class file (e.g., `FeatureWorker.ts`) for stateful components
- If the feature needs new tables, add to `src/modules/server/db/schema.ts` then `pnpm db:generate` + `pnpm db:push`

**New Server Function (API endpoint):**
- Add to the feature's `functions.ts`: `createServerFn({ method: "GET" | "POST" }).inputValidator(zodSchema).handler(...)`
- Consume from route `loader` or client action service in `src/modules/client/{feature}/service/`

**New Database Table / Column:**
- Edit `src/modules/server/db/schema.ts`
- Run `pnpm db:generate` to create migration SQL in `drizzle/`
- Run `pnpm db:push` to apply
- Add repository in `src/modules/server/{feature}/repository.ts`

**New Event Type:**
- Add Zod schema branch to `src/modules/server/events/schema.ts` (`EventSchema` discriminated union)
- Export the new schema and inferred type from the same file (re-exported via `events/index.ts`)
- Optionally add a pre-built handler in `src/modules/server/events/handlers.ts`
- Register the handler in `server/plugins/events.ts` if it should run globally

**New UI Component:**
- Cross-feature reusable → `src/components/` (e.g., `not-found.tsx`, `nav.tsx`)
- Ark UI wrapper (Panda-styled) → `src/components/ui/` (follow existing file patterns)
- Feature-scoped → `src/modules/client/{feature}/components/`
- Style via `css()` / patterns (`stack`, `hstack`, `vstack`) from `styled-system/`

**Shared Helpers / Utilities:**
- Client-safe, feature-specific → `src/modules/client/{feature}/utils/` or `service/`
- Server-only, feature-specific → `src/modules/server/{feature}/` (top-level file next to `repository.ts`)

**New Nitro Plugin:**
- Add to `server/plugins/{name}.ts` with default export `(nitroApp: NitroApp) => { ... }`
- Register in `vite.config.ts` inside `nitro({ plugins: [...] })`

**Tests:**
- Co-locate as `<source>.test.ts` next to the file under test (Vitest)

- Committed: Yes
- Rule: Never hand-edit

- Purpose: PandaCSS generated CSS utilities, JSX helpers, patterns, recipes, tokens, types
- Generated: Yes (`pnpm prepare`)
- Committed: Yes
- Rule: Never hand-edit

**`drizzle/`:**
- Purpose: Drizzle Kit SQL migrations + meta journal
- Generated: Yes (`pnpm db:generate`)
- Committed: Yes
- Rule: Never hand-edit — create a new migration instead

**`data/`:**
- Purpose: Runtime state (SQLite DB, spotdl logs, sync files)
- Generated: Yes (at runtime)
- Committed: No — gitignored; all persisted app data lives here

**`.output/`:**
- Purpose: Nitro SSR production build output
- Generated: Yes (`pnpm build`)
- Committed: No

**`.tanstack/`:**
- Purpose: TanStack tooling cache/tmp
- Generated: Yes
- Committed: No

**`patches/`:**
- Purpose: pnpm patch-package overrides for upstream dependencies
- Committed: Yes

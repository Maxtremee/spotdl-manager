## Trust Boundaries

| Boundary | Description |

| Client form → server fn | `sourceUrl` crosses from browser (untrusted) to server. Validated client-side (fast feedback) AND server-side (defense in depth — Plan 04 SyncRunner re-checks) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-03 | DoS | JSON-bomb / deeply-nested payload from EventBus consumer poisoning | mitigate | `z.enum` for `failureReason` caps shape to 5 strings; `z.number().int().nonnegative()` on `trackCount` caps to numeric; `z.boolean()` on `truncationSuspected` caps to bool. A malformed payload is rejected at `.parse` before consumers see it. |

Plan 04's SyncRunner re-validates server-side with identical logic (`isValidPlaylistUrl`). Test matrix proves the validator rejects `evil.example.com`, subdomains, and non-playlist/album paths. |
</threat_model>

<!-- The envelope contract the Python script emits. Plan 03 will parse this on the Node side with a matching Zod schema.  -->
<!-- Python writes exactly this JSON shape to stdout on stream-closed and exits 0. -->

Request (Node → Python stdin, single line JSON):
```json
{ "url": "https://open.spotify.com/playlist/<id>", "source_type": "playlist" }
```

Response envelope (Python → Node stdout, single JSON blob):
```json
{
  "tracks": [
    {
      "spotify_track_id": "6gkbtMtioHgtyGjrMel6ei",
      "title": "Track title",
      "artist": "Primary artist name",
      "duration_ms": 214000,
      "position": 0
    }
  ] ,
  "cover_art_url": "https://image-cdn-fa.spotifycdn.com/image/...",
  "error": null
}
```

Or on handled failure (Python exits 0):
```json
{
  "tracks": null,
  "cover_art_url": null,
  "error": { "type": "invalid_url" | "not_found" | "parse_error" | "network_error", "message": "..." }
}
```

On unhandled crash: Python exits non-zero, writes traceback to stderr, emits NO JSON on stdout. Node synthesizes `python_crash`.
</interfaces>

    1. Module docstring documenting request/response shape and exit-code contract (exit 0 on any emitted envelope — including handled errors; exit 2 only on unhandled crash).
    2. Imports: `json`, `sys`, `traceback`, `requests` (from spotifyscraper transitive deps), `from spotify_scraper import SpotifyClient`, `from spotify_scraper.core.exceptions import ParsingError`.

    5. Helper `_normalize(playlist: dict) -> tuple[list[dict], str | None]` — iterates `playlist.get("tracks") or []`, assigns `position = enumerate` index, skips any entry where `uri` is falsy (defensive; spike showed never happens on playlists), extracts `title = t.get("name") or ""`, `artist = artists[0].get("name", "") if artists else ""`, `duration_ms = int(t.get("duration_ms") or 0)`. Returns `(tracks, cover_art_url)`.
    6. Helper `_emit(envelope: dict)` — `sys.stdout.write(json.dumps(envelope)); sys.stdout.flush()`.
    7. `main() -> int`:
       - Read all stdin via `sys.stdin.read()`.
       - Parse JSON; on exception → emit `{tracks: None, cover_art_url: None, error: {"type": "invalid_url", "message": f"bad request: {e!r}"}}` and `return 0`.
       - Require `source_type == "playlist"` — else emit `invalid_url` envelope + `return 0` (album support is Phase 4; Phase 2 rejects non-playlist types).
       - Instantiate `SpotifyClient()`; call `client.get_playlist_info(url)` inside `try`.
       - `except ParsingError as e`: split into `not_found` (message matches case-insensitive `"not found"` OR contains `"404"`) vs `parse_error` (default). Emit envelope + `return 0`.
       - `except requests.exceptions.RequestException as e`: emit `network_error` envelope + `return 0`.
       - `except Exception as e`: write `UNEXPECTED: {type(e).__name__}: {e}\n` + full `traceback.print_exc` to stderr, `return 2` (no envelope emitted — Node classifies as `python_crash`).
       - `finally: client.close()`.
       - On success: call `_normalize(data)`, emit `{tracks, cover_art_url, error: None}`, `return 0`.
    8. `if __name__ == "__main__": sys.exit(main())`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Node → Python subprocess (stdin) | URL flows from server fn or scheduler into Python via stdin JSON; **never via argv** (command-injection prevention) |
| Python ↔ network (spotifyscraper → Spotify) | `requests` calls `open.spotify.com/embed/playlist/<id>` — URL validated Node-side before spawn; Python re-receives via stdin |
| Docker image layer boundary | `/app/scraper/.venv/bin/python` baked into immutable layer; runtime user `node` cannot modify it (T-2-07) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering/Elevation | URL flowing into `spawn` argv | mitigate | URL passed via stdin JSON only; `scraper.py` is the ONLY argv passed to `spawn`. Plan 03 enforces this at the Node side. This plan enforces it at the Python side by reading URL from stdin, not from `sys.argv` — `scraper.py` uses `sys.stdin.read()`. |
| T-2-02 | Tampering | Shell metachar in source URL | mitigate | `spawn('python3', ['scraper/scraper.py'])` (Plan 03) uses argv-form with `shell: false` (Node default); no shell interpolation anywhere on Node side. Python's stdin reader treats the entire stdin blob as JSON — no shell invocation. |
| T-2-05 | Info Disclosure | Python traceback leaks internal paths | mitigate | Unhandled exceptions write `traceback.print_exc` to **stderr** (goes to Pino logs only), NOT to the stdout envelope. The envelope's `error.message` field receives a short `str(e)` for handled errors — no traceback. Webhook formatter (Plan 05) reads the enum + short message, never stderr. |
| T-2-06 | DoS | Unbounded stdout buffering | accept | spotifyscraper's single-request design means one playlist → one JSON response ≤100 tracks → <100 KB stdout. Document in `scraper.py` module docstring that stdout is bounded by library's single-request shape (no streaming/chunked response). |
| T-2-07 | Tampering (TOCTOU) | `/app/scraper/.venv/bin/python` interpreter binary | mitigate | `COPY --chown=node:node scraper ./scraper` + `RUN ... && chown -R node:node /app/scraper` in the production Dockerfile BEFORE `USER node`. Binary lives in an immutable image layer; the non-root runtime user owns the tree but cannot swap the binary at runtime without container rebuild. |
</threat_model>

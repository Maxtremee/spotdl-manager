    ```typescript
    /**
     * Phase 2 integration test — real Python subprocess.
     *
     * GATED on SCRAPER_INTEGRATION=1. The scraper requires Python 3 + the
     * spotifyscraper venv at scraper/.venv/bin/python, which is only
     * guaranteed inside the Docker dev container (D-04 Docker-only dev).
     * Host `pnpm test` skips this file entirely so the fast feedback loop
     * stays fast.
     *
     * Run locally:
     *   pnpm docker:dev  # in another shell
     *   docker exec -it <dev-container> sh -c "SCRAPER_INTEGRATION=1 pnpm test -- integration"
     *
     * Fail modes handled: network errors during the live fetch are tolerated
     * (Spotify could be down); the test asserts contract correctness WHEN
     * the bridge returns a successful envelope. A network error envelope is
     * logged + the test is skipped-at-runtime with a message, not a hard fail.
     */
    import { describe, expect, it } from "vitest";
    import { SpotifyScraperBridge } from "./SpotifyScraperBridge";

    // Spike-001 known-good public playlist URL (Today's Top Hits or equivalent
    // from the spike's test fixtures). Replace with whatever the spike used —
    // check .planning/spikes/001-spotifyscraper-feasibility/ for the URL.
    const KNOWN_GOOD_PLAYLIST = "https://open.spotify.com/playlist/37i9dQZF1DXcBWIGoYBM5M";

    const gated = process.env.SCRAPER_INTEGRATION === "1";
    const d = gated ? describe : describe.skip;

    d("SpotifyScraperBridge (gated — real Python subprocess)", () => {
      it("fetches the known-good playlist and returns a shaped envelope", async () => {
        const bridge = new SpotifyScraperBridge();
        const envelope = await bridge.fetchPlaylist(KNOWN_GOOD_PLAYLIST);

        // Tolerant branch: if the live network failed, don't hard-fail —
        // the contract test is about shape, not network availability.
        if (envelope.error?.type === "network_error") {
          // eslint-disable-next-line no-console
          console.warn(
            "[integration] network_error — Spotify may be unreachable; skipping shape asserts",
            envelope.error.message.slice(0, 200),
          );
          return;
        }

        expect(envelope.error).toBeNull();
        expect(envelope.tracks).not.toBeNull();
        expect(envelope.tracks!.length).toBeGreaterThanOrEqual(1);

        const firstTrack = envelope.tracks![0];
        expect(firstTrack.spotify_track_id).toMatch(/^[a-zA-Z0-9]{20,30}$/);
        expect(firstTrack.title).toBeTypeOf("string");
        expect(firstTrack.title.length).toBeGreaterThan(0);
        expect(firstTrack.artist).toBeTypeOf("string");
        expect(firstTrack.duration_ms).toBeGreaterThan(0);
        expect(firstTrack.position).toBe(0);

        // cover_art_url can be null for playlists without art — but Today's
        // Top Hits always has art. If the spike's chosen URL changes, this
        // may need to relax to `typeof === "string" | null`.
        if (envelope.cover_art_url !== null) {
          expect(envelope.cover_art_url).toMatch(/^https:\/\//);
        }
      }, 60_000 /* timeout: 60s — real network + real Python */);

      it("fetches a deliberately invalid URL and returns a typed error envelope", async () => {
        const bridge = new SpotifyScraperBridge();
        const envelope = await bridge.fetchPlaylist(
          "https://open.spotify.com/playlist/DOES-NOT-EXIST-0000000000",
        );
        // Spotify may return parse_error or not_found depending on heuristic
        expect(envelope.tracks).toBeNull();
        expect(envelope.error).not.toBeNull();
        expect(["not_found", "parse_error", "network_error"]).toContain(envelope.error!.type);
      }, 60_000);
    });
    ```

    **IMPORTANT:** Before committing, verify the `KNOWN_GOOD_PLAYLIST` URL by reading `.planning/spikes/001-spotifyscraper-feasibility/`. If the spike used a different URL (e.g. the `RapCaviar` or `Mint` playlists), replace this constant. Using a URL that the spike ACTUALLY hit successfully is the only way to have confidence the test is meaningful.

    **Why `describe.skip`:** The standard Vitest pattern for conditional test inclusion. When `SCRAPER_INTEGRATION=1`, the real `describe` block runs; otherwise `describe.skip` produces "skipped" output and exits 0 instantly. No test body executes.

    **Why 60s timeout:** Python cold start (≤200ms per spike) + spotifyscraper fetch (<0.5s) + Zod parse (<10ms) = well under 1s in practice, but real networks hiccup. 60s absorbs one retry-worth of latency without false failures.

    **Why the "network_error early-return branch" in the success test:** This test is run against the LIVE Spotify site — if Spotify is down at test-time, we don't want a red build. The branch logs the issue and exits early; the shape contract is tested only when the live fetch actually worked. CI job runners that require determinism should set `SCRAPER_INTEGRATION=0` and rely on the unit-test bridge mock (Plan 03) for regression coverage.

       ```bash
       pnpm docker:dev
       ```
       Wait for the log line `Server running at http://localhost:3000` (or similar).

    2. **Python venv smoke (inside container):**
       ```bash
       docker exec -it <dev-container-name> sh -c "/app/scraper/.venv/bin/python -c 'import spotify_scraper; print(spotify_scraper.__version__)'"
       ```
       Expected output: `2.1.5`

    3. **Integration test (inside container):**
       ```bash
       docker exec -it <dev-container-name> sh -c "SCRAPER_INTEGRATION=1 pnpm test -- integration"
       ```
       Expected output: 2 tests pass (or 1 pass + 1 early-return with network_error warning).

    4. **UI smoke — add a source + Sync-now:**
       - Open http://localhost:3000 in a browser
       - Navigate to Library → Add playlist
       - Paste the spike-001 known-good URL (or any public Spotify playlist ≤100 tracks)
       - Set output dir to `/data/music/test-phase-2`
       - Submit
       - Open the new playlist's detail page
       - Click "Sync now" button (should be enabled now — Phase 1 hid this button)
       - Wait for the toast "Sync started" then the loader invalidation

    5. **Verify DB state:**
       ```bash
       docker exec -it <dev-container-name> sqlite3 /app/data/db.sqlite \
         "SELECT count(*), state FROM tracks GROUP BY state;"
       ```
       Expected: ≥1 row with `state = pending`. Count should match the Spotify playlist's track count (≤100).

    6. **Verify sources.cover_art_url populated (SCRAPE-07):**
       ```bash
       docker exec -it <dev-container-name> sqlite3 /app/data/db.sqlite \
         "SELECT name, cover_art_url FROM sources;"
       ```
       Expected: `cover_art_url` is a non-null `https://image-cdn-fa.spotifycdn.com/...` URL (or similar CDN host).

    7. **Verify invocations row:**
       ```bash
       docker exec -it <dev-container-name> sqlite3 /app/data/db.sqlite \
         "SELECT status, summary FROM invocations ORDER BY started_at DESC LIMIT 1;"
       ```
       Expected: `status = success` and summary JSON contains `track_count: N, truncation_suspected: false` (or `true` if you picked a >=100-track playlist).

    8. **(Optional) Discord webhook check:**
       If a Discord webhook is configured in settings, verify:
       - The completion message renders the playlist name + duration + track count line
       - If the playlist is ≥100 tracks, the "⚠️ possibly truncated" note appears

    9. **(Optional) Failure path smoke:**
       - Create a source with a deliberately bad URL: `https://open.spotify.com/playlist/DOES-NOT-EXIST-0000000000`
       - Click Sync now
       - Verify: invocations row has `status = failed` and summary JSON contains `failure_reason: "not_found"` OR `"parse_error"`
       - If Discord webhook configured: the failure message includes `reason: \`not_found\`` (or equivalent enum)

    **Pass criteria:** Steps 1-7 all produce expected output. Steps 8-9 are nice-to-have and can be skipped if webhook isn't set up.

    - Button missing / doesn't trigger sync → UI plan (Plan 05) bug

## Project Overview

A browser-based UI for managing playlists downloaded via spotdl, with scheduling and automatic refresh capabilities. Built with Solid.js, TanStack Start (SSR), SQLite via Drizzle ORM, and PandaCSS.

## Commands

```bash
pnpm dev          # Start dev server (port 3000)
pnpm build        # Build SSR output to .output/
pnpm start        # Run SSR server (use this to test SSR, not pnpm preview)

pnpm format       # Format with Biome
pnpm lint         # Lint with Biome
pnpm check        # Full Biome check

pnpm test         # Run Vitest
pnpm prepare      # Generate PandaCSS utilities (run after theme changes)

pnpm db:push      # Apply migrations
pnpm db:generate  # Generate Drizzle types
pnpm seed         # Seed database with sample data
```

## Architecture

### Module Structure (client/server boundaries)

```
src/modules/
├── client/           # Client-safe code (bundled in SPA)
│   └── [feature]/
│       ├── schema/   # Zod validators and types
│       ├── service/  # Business logic, formatters (no side effects)
│       ├── components/
│       └── utils/
│
└── server/           # Server-only code (Nitro/Node)
    ├── db/           # Schema, initialization, seeding
    └── [feature]/
        ├── repository.ts  # Data access layer (Drizzle queries)
        └── functions.ts   # Server functions (createServerFn)
```

**Never import server code into client bundles.**

### Data Flow (SSR)

1. Route defines `loader` using server function
2. Server function calls repository layer
3. Repository returns paginated data via Drizzle
4. Client accesses via `Route.useLoaderData()`

### Routing

File-based routing via TanStack Router in `src/routes/`. The route tree is auto-generated in `routeTree.gen.ts` - do not edit this file.

### Styling

- PandaCSS utilities generated from `panda.config.ts` to `styled-system/`
- Theme tokens in `src/theme/tokens/`
- Use `css()` from `styled-system/css` for styling
- Run `pnpm prepare` after changing theme configuration

### UI Components

61 pre-built components in `src/components/ui/` wrapping Ark UI primitives. Use these instead of raw Ark UI imports.

### Validation

All inputs validated with Zod. Schemas live in `src/modules/*/schema/`. Server functions use `.inputValidator()` for type-safe validation.

## Generated Files (Do Not Edit)

- `src/routeTree.gen.ts` - TanStack Router tree
- `styled-system/**` - PandaCSS generated utilities
- `drizzle/` - Migration files

## Database

SQLite with Drizzle ORM. Single `playlists` table with fields for source configuration, spotdl flags, scheduling, and status tracking. Database file: `data.db`.

### Logger

Singleton pino-based logger in `src/logger.ts`. Use module-scoped loggers for context:

```typescript
import { Logger } from "~/logger";

const logger = Logger.get("MyModule");  // Scoped logger
logger.info("Operation completed");
logger.error("Failed", { error });
```

- Development: Pretty-printed with colors
- Production: JSON output
- Configure level via `LOG_LEVEL` env variable

### Event Bus

Type-safe pub/sub system in `src/modules/server/events/`. Used for decoupled communication between server components.

```typescript
import { getEventBus } from "~/modules/server/events";

const bus = getEventBus();

// Subscribe to events
const unsubscribe = bus.on("playlist.sync.completed", async (event) => {
  console.log(event.payload.playlistName);
});

// Emit events
await bus.emit({
  type: "playlist.sync.started",
  payload: { playlistId, playlistName, invocationId, sourceUrl, outputDir },
});
```

**Event Types:**

- `playlist.sync.started/completed/failed/canceled` - Sync lifecycle
- `playlist.created/updated/deleted` - Playlist CRUD
- `scheduler.reload` - Trigger scheduler refresh

**Pre-built handlers** in `handlers.ts`: logging, metrics, failure notifications, scheduler reload, duration warnings, log cleanup.

**Server integration** via Nitro plugin in `server/plugins/events.ts`.

## Key Patterns

- Use `~/` path alias for imports
- Functional components only in Solid.js
- Business logic in service layer, not components
- All server mutations via `createServerFn`
- Test SSR with `pnpm start`, not `pnpm preview`
- Use `Logger.get("ModuleName")` for server-side logging
- Emit events via EventBus for cross-cutting concerns (webhooks, metrics, etc.)
